# 通知功能实施计划

署名：Carinoasd

## 范围

完善登录、到期提醒、工单更新、定时任务失败与恢复四类事件。管理员分别控制 Telegram 与邮件管道，用户选择自己的到期提醒及工单邮件通知。现有 Telegram 行为与登录邮件默认保持；新增邮件管道默认关闭。

不修改 CORS／CSRF。验证码、找回密码、Bot 指令回复继续使用原流程。QR 绑定／登录及 2FA 分别在后续批次实现。

## 顺序与验收

1. **基线**：从已合并 #112 的 main 建独立分支，确认原有偏好及工单隐私边界。
2. **配置**：加入八个事件／管道开关，覆盖 TOML、环境变量、后台配置及保存往返。加入工单邮件、到期邮件及到期 Telegram 个人偏好；旧账号保留到期 Telegram 默认。
3. **传送**：复用 SMTP 客户端，只向已验证邮箱发送。工单用户邮件不能包含内部备注，管理员不接收自己的工单操作通知。Telegram 失败不阻止 Email 尝试，取消仍能终止批次，摘要分管道计数。
4. **界面**：按事件及管道显示个人设置；缺少绑定、管理员关闭时提示。保存期间防重复，失败不能留下已保存的假象。补齐简体、繁体与英文文案。
5. **验证**：用本机模拟 Telegram／SMTP 测试独立开关、未验证邮箱、个人静音、工单隐私、失败隔离及取消。验证配置与个人偏好重新加载、前端类型／lint／构建、完整后端 PostgreSQL 套件，检查 CORS／CSRF 无差异。
6. **交付**：写明默认值、限制及测试证据，推送分支，在上游开独立 PR，留给维护者审查。

## 边界

沿用有超时的现有通知流程，不新增持久化邮件队列。进程退出或上游不可用时不保证必达；不扩大自动重发范围，避免重复通知。关闭事件邮件不影响验证码等认证邮件。
